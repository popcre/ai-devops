## 1. Ultimate goal
Albert's past AI chat transcripts are cut into topic segments in one SQLite
"transcript store" that every AI session can query. The goal: the store never
silently mislabels or merges conversations, and the daily refresh never
"succeeds" while doing nothing. **If a step conflicts with this goal, the goal
wins — stop and flag it.**

## 2. What this application is
`popcre/ai-devops` (public) is Albert's AI toolkit. The transcript store:
`tools/transcript_store/` (Python: `normalize.py`, `segment.py`, `build.py`),
built daily on edge-dev3 (Linux) by systemd user timer
`ai-transcript-store.timer` → `~/.config/ai-devops/transcript-store/ai-transcript-store-run`,
installed by `bin/ai-install-transcript-store`. Calls ScaleDown (an LLM-ish
segmentation API) with prompt file `prompt_v<N>.txt`. Background:
`plan_transcript-store.md` (closed 2026-10-31, all steps done).

## 6. Key findings
- `lineage_for` (`build.py:179-197`) picks the existing row ordered by
  `first_ts IS NULL, first_ts` — no tie-break, so equal timestamps depend on
  processing order.
- `lineage_id` = a session_id, which can fall back to the file stem
  (`normalize.py:279` area) and so may collide across machines; `rekey_lineage`
  then rewrites the wrong group and can hit the `seen_turns` primary key
  `(lineage_id, turn_hash, occurrence_no)` → `IntegrityError` aborts the build.
- `relabel()` (`build.py:378+`) keeps `*_relabel` side tables across
  interrupted runs; a normal build in between can rekey main tables only.
- Runner `flock -n 9` with no flock binary returns 127, `!` makes it print SKIP
  and exit 0.

## 7. Rejected approaches
- Full `docs/locks.md` op protocol (`-E 87`, `ai-lock-doctor`, retry) in the
  installer: skinny rulings 2026-10-29/30 — one manual run per install, a
  clear error is enough.
- Re-keying by rebuilding the whole store: too costly (ScaleDown calls).
- Making the store multi-writer/Windows: out of scope; writer is edge-dev3 only.

## 8. Decisions
Locked: lineage id remains the earliest file's session_id; reviews are advisory;
no new blocking checks. Open: exact tie-break key — use smallest `path`
(stable, unique) unless the implementer finds a better unique column.

**Step 2 — #2103 (after Step 1 or parallel).** In `build.py`:
- `lineage_for` query: `ORDER BY first_ts IS NULL, first_ts, path LIMIT 1`;
  rekey condition also rekeys when `first == row[1]` and `path < row_path`
  (select `path` too). Result: same lineage id regardless of processing order.
- `rekey_lineage(old, new, key)`: restrict each UPDATE to rows whose session
  has `lineage_key=key` — sessions: `WHERE lineage_id=? AND lineage_key=?`;
  chunks/seen: `WHERE lineage_id=? AND lineage_id IN (SELECT lineage_id FROM sessions WHERE lineage_key=?)`
  is NOT enough when ids collide, so first check:
  `SELECT count(DISTINCT lineage_key) FROM sessions WHERE lineage_id=old`; if
  >1, skip the rekey (keep `old`, log a counted `rekey_skipped` stat) rather
  than corrupt. Wrap all UPDATEs in one transaction; catch
  `sqlite3.IntegrityError` → rollback, skip, count.
- Also apply the same UPDATEs to `chunks_relabel` and `seen_turns_relabel`
  when those tables exist (regardless of `self.t`).
- Gate: new tests (section 10) pass; existing `test_fork_lineage_id_is_earliest_by_first_ts` still passes.
