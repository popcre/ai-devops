SUGGESTED DIAGNOSIS DIRECTIONS
1. Determine whether the session-creation step can hang or fail without writing state and
   without emitting anything on stdout or stderr. If it can, that is the bug: a wrapper
   should never be able to occupy a reviewer slot while leaving no trace it started.
2. Emit a line at session creation -- before any provider call -- naming the session and its
   state file path. That single line distinguishes "never started" from "started and
   working" and would have answered this in one second instead of seventeen minutes.
3. Consider a startup watchdog: if no state file exists N seconds after invocation, fail
   loudly with a distinct code rather than continuing silently.
4. Check whether the earlier `.ai/reviews` refusal path can leave residue that affects a
   later run in a different clone (shared lock, shared state directory, stale caller
   mapping), given both of today's runs touched that path.
