# Disposable Jujutsu pilot — 2026-09-27 EDT

## Verdict

**No-go for an opt-in rollout or default switch.** Six paired Git/Jujutsu task trials preserved all edits and produced equal file trees. Two clean Jujutsu branches exported to independent bare Git remotes, read back as ordinary Git commits, and passed focused repository tests. However, a harmless untracked file automatically entered a Jujutsu working-copy commit during `jj status`. Jujutsu workspaces added with `jj workspace add` also had no `.git` directory, so direct Git-based tooling failed there. The first finding triggers the plan's untracked-import privacy stop. Neither the trial nor this report changes installed routing, GitHub branches, database state, or the default Git workflow.

These are small, serial, local trials, not request-to-verified-outcome measurements. The [Step 0 baseline](2026-09-27-agent-evidence-jj-baseline.md) found 14 evidence-only commits in eight selected shared-db PRs and three main merges in two selected ai-devops PRs, but does not isolate end-to-end delay. A median or p90 business impact comparison would be unsupported.

## Git export, compatibility, and privacy checks

For the clean conflict case in each repository, `jj bookmark set pilot-export -r @`, `jj git remote add trial PATH_TO_NEW_BARE_REPO`, and `jj git push --remote trial --bookmark pilot-export` exported to a separate local bare repository. A fresh `git clone --branch pilot-export` read back each commit. Ai-devops readback commit `e97fc067eb61c5cdf24d81a190c485317dd9440b` had tree `a95bb94c1b1617bf9fd9ccd668f97c2b7bfc3c59`; shared-db readback commit `418e3dcdb1c0e15dd42f3acbe51a3505b075cab7` had tree `837fded494dcbb2a97c6fc748d4e0c103f8add90`. Both equal their paired Git trial trees. Both readback clones returned `true` for `git rev-parse --is-inside-work-tree` and clean `git status --short`. Ai-devops retained the `transcripts` gitlink at `e1d2a7ed893647ea4caef177600850b9d263e17f`; Jujutsu reported that it ignored the submodule working directory while cloning. Normal Git rollback needs only the exported branch in a normal Git clone; no conversion was needed. The bare test remotes remain under `/tmp/jj-pilot-911/trials/` for this session's audit and are not GitHub remotes.

Focused test from the **ordinary exported Git clone**: `bash tests/test-ai-review-packet.sh` gave **145 passed, 0 failed**; shared-db `node --test scripts/check-main-tip-freshness.test.mjs` gave **26 passed, 0 failed**. This proves these tools can inspect the exported branch; it does not prove a full CI or protected GitHub merge.

The colocated Jujutsu clone root returned `.git` from `git rev-parse --git-dir`. A workspace created with `jj workspace add` returned Git exit **128** for the same command in both repositories. Existing repository scripts that invoke Git therefore need a normal exported Git checkout or explicit adaptation before any rollout. No colocated Jujutsu/Git repository was concurrently mutated across machines, consistent with the [upstream concurrency warning](https://jj-vcs.github.io/jj/latest/technical/concurrency/).

Privacy control: ai-devops `.gitignore` ignores `*.env`. A trial `.env` containing only the text `pilot-only-placeholder` stayed out of `jj status` and the Git tree. A harmless `pilot-untracked.txt` **appeared as an added path on `jj status` and entered the working-copy commit** without an explicit add command. It was immediately removed by `jj restore`; neither file was exported. This is a stop condition under the Step 4 gate and requires a privacy safeguard/review before any live trial. No actual secret was placed in a trial. Ordinary Git's untracked status did not add the interrupted file until the explicit `git add` after recovery.

## Shared-db migration guard trial

Only disposable clones added `supabase/migrations/20260925193145_pilot_collision.sql` containing `select 1; -- pilot only`, deliberately reusing an existing migration version. Git and Jujutsu produced the identical branch tree `5e390a6e527def9ab92c8b119dde3d66b635d197`. The Jujutsu trial branch exported to a third bare Git remote; fresh Git readback commit `b8f743d6841baed4d60cecb546a348681248673b` retained that tree. In each ordinary Git checkout, an unrelated `scripts/pilot-main-advance.txt` commit advanced a local main branch. Calling the repository's `classifyBranchFreshness({headSha, tipSha, cwd})` returned `ok: false` and this decisive reason in both cases: `migration version collision on main: supabase/migrations/20260925193145_pilot_collision.sql and supabase/migrations/20260925193145_licensing_candidate_and_review_apis.sql.` The branch was never pushed to GitHub or a database. This proves export does not bypass the existing version guard. The database object claim, protected checks, and guarded merge would still be required for a real migration; this offline test did not execute those gates.

## Decision boundary

Zero tested edits were lost, export produced ordinary equal-content Git trees, and the migration version refusal survived export. The automatic untracked import is a privacy stop, and added workspaces cannot run Git tooling directly. Retain Git worktrees. A separate reviewed opt-in proposal would first need a proven exclusion/snapshot policy for untracked sensitive files, Git-tool compatibility in each agent workspace, and prospective request-to-verified-outcome measurements. This report requests no installation or rollout.
