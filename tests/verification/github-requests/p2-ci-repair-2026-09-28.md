# P2 CI repair review evidence — 2026-09-28

This note covers the P2 repair after pull request #929 failed its qualified
Windows offline job. The failure was twelve `test-ai-gh.sh` assertions:
seven symlink fixtures did not create real links under Git Bash, and five raw
GraphQL cases reached native Windows `jq` through a FIFO file descriptor it
could not read. The fix retains the response stream, passes it to `jq` through
an anonymous pipe, and classifies pages with bounded state and no separate
classifier timeout. The response body is not written to quota state.

## Deliberate boundary

Ad hoc `gh api graphql` calls with `--jq`, `--template`, `--silent`, or
`--include` retain their CLI output and exit status. In the installed `gh`
v2.101.0, [the CLI checks JSON GraphQL errors before formatting or suppressing
output](https://github.com/cli/cli/blob/v2.101.0/pkg/cmd/api/api.go#L451-L520).
Its parser fails when an error has a nonempty message. The wrapper cannot
independently inspect transformed bodies, so malformed or empty-message error
objects that the CLI misses remain unclassified. A local HTTPS fixture tested
the real installed CLI with each of the four flags: success returned zero,
`errors:[{"message":"field unavailable"}]` returned one, and `errors:[{}]`
returned zero. Each variant made exactly one request; the 12 variants made 12
requests total. No GitHub service request was made for this proof. The managed
merge queue proof now reads raw GraphQL through `ai-gh`, checks partial errors,
and then applies external `jq`; the source guard also covers the managed waiter
and BlockerWatch callers.
