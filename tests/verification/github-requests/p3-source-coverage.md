`tools/ci/check-managed-github-transport.py`, owned by #931, scans installed `bin/` commands in the existing workflow-policy suite. It rejects a new direct CLI (including Windows `gh.exe`), literal CLI aliases, line-split commands, Node CLI or GitHub HTTP/SDK source; tests prove a legitimate delegated fake transport passes and injected bypasses fail. P4/S2 retired the direct waiter fallback. The bootstrap Git clone and user-facing command examples have narrow literal exceptions. This guard is necessary because the existing policy tests did not cover newly added managed callers; it stays as the regression gate.

The P3 callers `ai-merge-group-evidence`, `ai-transcript-destination-check`, `ai-workspace-status`, and `ai-reviewer-membership-drift` have fixed labels in both the local telemetry collector and offline report parser. A caller-supplied unknown or injected value remains `unknown`; neither argv nor private response content becomes a label. The Windows runner maintenance route currently remains `unknown` in this local attribution until its separate installed proof establishes the supported caller identity.

No response cache is used for collision, exact-SHA, merge-queue or private visibility decisions. The fake transports run offline with isolated state. Success/failure status and CLI output continue to come from the underlying command. Installed and CI proof must be linked on #931 before this disposition is accepted as complete.

All other managed GraphQL calls surveyed (`ai-pr-wait` and `ai-blocker-watch`) already consume raw JSON without `gh api` output transforms. The `--jq` flags on `gh run`/`gh repo` commands do not transform a direct GraphQL API response. This distinction lets P2's streamed `.errors` classifier see the raw response without an extra GitHub request.
